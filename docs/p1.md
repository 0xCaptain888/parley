# P1 Command Reference

These are the optional extensions described in source sections 6.3, 7.4 and 7.5. They do not change the supplied contract, wallet authority or per-call confirmation rules. The source did not prescribe exact `deal start` flags; the explicit syntax below is this implementation's interface.

## Watch

```sh
node parley.mjs watch --from <me>
node parley.mjs watch --interval 15 --limit 50 --from <me>
node parley.mjs watch --once --from <me>
```

Polls inbox storage. Interval is 5-3600 seconds; limit is 1-50. Each output is one JSON object on one line. Normal mode emits only new items. `--once` always returns a snapshot. Ctrl-C / SIGTERM stops the watcher. No acknowledgement, transfer, signature, automatic reply or execution is performed.

The per-process cursor advances after output, not the persistent acknowledgement cursor. Restarting may re-emit unacknowledged items. `ack` remains an explicit user-facing action. Long backlogs page through storage rather than relying on logs.

## Bounded Negotiation

The unit-token amounts are **total consideration for the whole fixed asset quantity**, not a floating-point unit price. Every user must explicitly set their own boundaries; mail can never create a session or rewrite its limits.

Seller:

```sh
node parley.mjs deal start --to bob --side sell \
  --asset-token BNB --asset-amount 0.001 --unit USDT \
  --target 0.6 --floor 0.5 --rounds 5 --ttl 3600 --from <me>
```

Buyer joins the returned thread, only when independently authorized by its user:

```sh
node parley.mjs deal start --thread <thread> --to alice --side buy \
  --asset-token BNB --asset-amount 0.001 --unit USDT \
  --target 0.55 --ceiling 0.65 --rounds 5 --ttl 3600 --from <me>
node parley.mjs deal next <thread> --from <me>
```

Add `--with-postage` only after the user explicitly agrees to a first-contact stamp. Default rounds: 5; allowed: 1-20. TTL: 600-604800 seconds, default 3600.

Sessions are in `policy.json.sessions`. Targets, floor/ceiling, assets, peer, expiry and round cap are immutable through this CLI once created. A thread is 16 random hexadecimal characters, or a user-authorized existing thread when joining. The private session state is not uploaded. Neither the helper nor `watch` invokes `baw`.

Each `deal next` evaluates only valid, authenticated kind-2 mail from that peer and thread. Tokens and fixed quantity must match. Sequences must increase. Invalid schemas, repeated/expired messages and unknown sessions fail closed. Opponent strings never determine numeric boundaries.

For a seller, concession at round `r` is `target - (target - floor) * r / rounds`, using integer division; the buyer is symmetric toward its ceiling. One run prepares at most one step. No crossing of the user's floor/ceiling is permitted. After all concession rounds, an unmatched quote produces a rejection proposal.

## Settlement State

1. `deal start` prepares an encrypted nonbinding quote. Its local sequence advances only after the matching receipt confirms.
2. `deal next` prepares a counter-quote, rejection or binding `createOffer` within local bounds. Token approval, when required, must be confirmed first; rerun the same command afterward.
3. After creation confirms, the maker's next `deal next` prepares an encrypted `accept` notification containing the real `offerId`.
4. The peer independently verifies actual maker, named taker, tokens, quantities, open status, expiry and its own bound. Its next call is a separately previewed and confirmed `acceptOffer`.
5. The maker can refresh `deal next` to observe settlement. Quote text itself never settles a trade.

`result --plan <id>` applies session state once; repeated receipt handling is idempotent. Recent unresolved steps return `DEAL_PENDING`; no new mail returns `NO_NEW_QUOTE`. The local session expiry cannot be extended by the peer. The actual on-chain TTL starts at mining time, so its expiry can differ slightly from the local deadline; the helper stops preparing steps at its own deadline.

The bound is on nominal token quantities, not USD value. It is not a price oracle. Transfer-tax/rebase tokens are unsuitable for fixed-quantity negotiation; a mismatch between an actual escrow and its notification is refused. Manually cancelling an open offer remains available through the P0 `offer cancel` command.

## English Website

All six routes support `?lang=en`, preserving explicit demo mode and navigation. Language changes affect only trusted UI, safety disclosures and copied instructions. Greetings and other author-provided content remain original, marked untrusted and rendered as text. The English website does not make the unaudited contract, local video or fictional demo metrics production-ready.
